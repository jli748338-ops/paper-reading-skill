# 论文详细阅读文件结构

输出 Markdown 必须按下列顶层顺序组织。核心原则是：**导航与综合分析可以使用统一框架，论文主题内容必须按原文顺序精读。** 不得为了套用分析类别而拆散作者原有的章节、方法链或实验流程。

## 0. 阅读导航

- 用一句话概括论文解决的问题、所用方法和主要结果。
- 列出论文原有章节及其顺序，说明每一章在论证中的作用。
- 建立“问题→方法→数据/训练→实验→结论”的总体链条，但这里只提供导航，不提前替代后面的正文精读。

## 1. 论文基本信息

- 中英文标题、作者、通讯作者和机构。
- 预印本与正式发表时间，期刊/会议/主会/Workshop 的准确身份。
- 在可核实条件下报告 CCF、CORE、JCR、中科院分区等适用评级，说明评级对该论文是否真正适用。
- 论文类型：理论、方法、数据集、benchmark、系统、应用、调查等。
- 官方项目页、代码、数据、模型和许可证状态。

发表信息与评级必须区分官方事实和通行评价，不用发表地替代对单篇论文的评价。

## 2. 摘要与核心贡献

- 按“背景→问题→方法→实验→结论”重构摘要，不逐句翻译。
- 分条列出论文自称的贡献，标记各贡献由哪个方法、图表或实验支持。
- 区分资源/数据贡献、方法贡献、实证贡献和概念性主张。
- 本节只建立阅读预期；详细方法和实验证据留在正文原位置解释，不在这里提前拆完。

## 3. 正文顺序精读

这是交付文件的主体。以论文原有的 section/subsection 为骨架，从第一节到结论逐节展开。

### 3.1 结构规则

1. 按论文目录或正文出现顺序创建小节，尽量保留原文编号和标题，例如 `### 3.1 原文 Section 1: Introduction`、`### 3.2 原文 Section 2: Related Work`。
2. 原文一个小节内部也按段落论证顺序讲解：作者先提出什么、随后定义什么、再引出哪个模块或实验，就按该顺序复述和解释。
3. 不得把原文的方法拆成自定义的“架构汇总→公式汇总→图表汇总”，也不得把实验拆成“结果数字汇总→统一图表解读”后再回讲流程。
4. 如果原文先讲方法 A、再展示 Figure 2、然后给 Equation 3、最后引出方法 B，笔记也应按 A → Figure 2 → Equation 3 → B 的顺序展开。
5. 可在每个原文小节末尾增加简短的“本节小结/证据评价”，但不得把尚未在原文出现的后续内容提前搬入。

### 3.2 图、表、公式与算法的就地讲解

图、表、公式和算法是正文论证的一部分，必须在首次出现或首次被实质讨论的位置立即解释。

每张关键图表在当前位置说明：

- 它承接前文哪个问题，在论证中起什么作用；
- 轴、行列、图例、颜色、标记或流程箭头如何阅读；
- 主要观察、关键数字和比较对象；
- 作者据此得出的结论；
- 替代解释、局限，以及它不能单独证明什么。

每个重要公式在当前位置说明：

- 符号、输入、输出和维度（论文可知时）；
- 计算步骤及其直观意义；
- 它是定义、模型变换、训练目标、正则项、约束还是推理规则；
- 与前一个模块和下一个模块的关系；
- 论文未说明或表述含混之处。

每个算法或伪代码在当前位置按执行顺序解释输入、循环/分支、更新对象、输出、复杂度和停止条件。

同一图表在后文再次被引用时，可回链首次解读位置并补充新的论证作用，不要重复整段解释。末尾图表导航只列索引，不替代这里的正文解读。

### 3.3 理论、方法与架构的顺序精读要求

遇到理论或方法章节时，沿用论文自己的 subsection 顺序。对每个模块在其原位置说明：

1. 它要解决的局部问题；
2. 输入和前置条件；
3. 计算或处理步骤；
4. 输出；
5. 与前后模块的衔接；
6. 同位置出现的 figure/table/equation/algorithm；
7. 设计理由、代价和关键假设；
8. 论文未说明的实现细节及其复现影响。

总体架构图出现时，就地按图中的阅读顺序解释整条信息流。后续正文逐模块展开时，再补充各模块细节；不要在一个脱离原文位置的“总体图表章节”中集中讲完。

### 3.4 数据、训练与推理的顺序精读要求

- 数据在原文何处首次定义，就在何处解释来源、规模、筛选、预处理、划分、标签、许可和潜在泄漏。
- 如果数据集只在实验章节出现，不要为了统一模板而提前把详细数据分析搬到方法之前；前面只保留理解任务所必需的最小定义。
- 按原文顺序说明原始数据如何成为模型样本，多模块、多模态或多尺度信息如何融合。
- loss、正负样本、损失权重、优化器、训练阶段、冻结/解冻和超参数在原文出现处就地解释。
- 推理流程在原文出现处说明如何从输入得到最终输出，并区分训练专用组件与推理组件。

### 3.5 实验流程与结果的顺序精读要求

实验章节必须沿用论文原有顺序，例如论文若按 `Datasets and Metrics → Implementation Details → Main Results → Ablation → Qualitative Results` 展开，笔记也使用同一顺序，不改排为自定义实验类别。

在每个原文实验小节内，随作者叙述依次说明：

1. 验证的问题或主张；
2. 数据、模型和实验设置；
3. 自变量、控制变量和 baseline；
4. 评价指标及方向；
5. 当场出现的 table/figure 读法；
6. 定量结果，包括绝对值、差值和必要的相对变化；
7. 作者解释；
8. 证据评价，包括公平性、方差、置信区间、显著性和结论边界。

不得只写“优于 baseline”。必须说明优于谁、哪个指标、多少，以及是否控制训练预算、数据和模型规模。

消融、敏感性、扩展律、定性结果和失败案例也放在原文对应位置。保留负面、无效或不一致结果；如果论文没有失败案例或误差分析，在实验章节结束处明确记录。

### 3.6 逐节写作模板

对每个原文 section/subsection，可按下列顺序写，但不必机械显示全部标签：

1. **本节在原文中的任务**；
2. **按段落顺序讲解正文内容**；
3. **遇到图/表/公式/算法即就地插入解读**；
4. **本节结论与下一节衔接**；
5. **就近证据评价与未说明事项**。

## 4. 附录与补充材料顺序精读

- 按附录 A、B、C 或补充材料原有顺序阅读，不按主题重新归类。
- 附录中的方法细节、证明、额外实验、图表和公式同样在其出现位置就地讲解。
- 当附录补充或修正正文内容时，先说明它对应正文哪一处，再解释新增信息。
- 检查正文与附录之间的数字、定义、超参数和结论是否一致；矛盾必须明确记录。
- 没有附录或补充材料时，保留本标题并写明“论文未提供”。

## 5. 结果综合与假设回收

- 在完成正文和附录顺序精读后，建立“核心假设/主张→支持实验→证据强度→结论”对照表。
- 区分“得到支持”“部分支持”“未验证”和“与结果矛盾”。
- 检查作者是否将下游任务效果过度外推到更强的能力主张。
- 这里可以跨章节综合，但不要用综合部分替代前面的顺序精读。

## 6. 结论、局限与批判性评价

### 6.1 论文结论

用论文本身的证据范围重述结论，不复制摘要。

### 6.2 主要优点

按问题价值、方法、数据、实验与可复现性分类。

### 6.3 局限性

区分：作者报告的局限；方法假设导出的局限；实验未覆盖的问题；数据、伦理、隐私、版权、偏见和能耗问题；统计口径、图表、方法与附录之间的矛盾或模糊表述。

### 6.4 未来工作

区分作者建议与基于局限的阅读者建议。

### 6.5 总体评价

说明论文的真正增量、证据最强与最弱的地方，以及结论适用范围。

## 7. 复现与资源检查

- 数据、代码、模型、训练配置和许可证是否可得。
- 硬件、计算时间和费用级别。
- 随机种子、超参数、数据处理与评测代码是否完整。
- 对照代码、正文和补充材料，记录实现与论文描述的不一致。
- 给出“可直接复现/需要重要补充/当前难以复现”的判断及依据。

## 8. 关键信息索引

- 关键数字速查表。
- 图表导航：figure/table 编号、原文所在 section/page、主题、支持的主张。这里只做索引，不重新集中解读图表。
- 核心概念与缩写表。
- 后续可追问问题，覆盖背景、方法、loss、实验、数据质量和局限。

## 写作约束

- 正文精读部分优先保留原论文的标题、编号、顺序和前后衔接；统一分析框架只用于导航、综合评价和索引。
- 图、表、公式和算法在原文首次出现处就地解释，不设置脱离正文顺序的独立“图表解读”或“公式汇总”章节。
- 使用清晰的多级 Markdown 标题和必要表格，不为了结构而过度分点。
- 详尽意味着解释关系、证据和限制，不是重复摘要或堆积原文。
- 对重要判断就近标记来源 section/page/figure/table。
- 对外部核对信息使用可追溯链接，优先官方出版页、会议/期刊页、作者项目页和官方代码仓库。
- 如无法验证信息，明确说明无法验证，不使用印象性排名。
